# MULTI-ECU SCHEDULING
This project explores scheduling strategies and algorithms for coordinating tasks across multiple Electronic Control Units (ECUs) in automotive and embedded systems. The repository provides reference implementations, scenario definitions, evaluation scripts, and documentation to help researchers and engineers prototype, compare, and evaluate scheduling approaches for distributed embedded systems.


## Features

- Reference implementations of scheduling algorithms (e.g., EDF, Rate Monotonic, custom heuristics)
- Multi-ECU scenario definitions and task models
- Simulation and evaluation scripts to measure scheduling metrics (latency, jitter, CPU utilization)
- Example configurations for different ECU topologies and communication delays

## Getting started

These instructions assume you have Python 3.8+ installed. Adjust commands if you use a different environment or package manager.

1. Clone the repository

   ```bash
   git clone https://github.com/Aditi-Gp/multi_ecu_scheduling.git
   cd multi_ecu_scheduling
   ```

2. (Optional) Create and activate a virtual environment

   ```bash
   python -m venv .venv
   source .venv/bin/activate   # macOS / Linux
   .venv\Scripts\activate     # Windows (PowerShell)
   ```

3. Install dependencies

   If a requirements.txt file exists:

   ```bash
   pip install -r requirements.txt
   ```

   Otherwise, install needed packages as you go (e.g., numpy, matplotlib).

## Usage

- Put or edit scenario and task definition files under `scenarios/` (or the directory used by the code).
- Run the simulation or scheduler driver. Example (replace with the actual script name if different):

  ```bash
  python run_simulation.py --scenario scenarios/example.yaml --algorithm edf
  ```

- Results and logs will appear in the `results/` directory (or the configured output path).

## Suggested project layout

- `algorithms/` — scheduling algorithm implementations
- `scenarios/` — scenario and taskset definitions
- `sim/` or `engine/` — simulation engine and helpers
- `tools/` — utilities for analysis and plotting
- `examples/` — example runs and expected outputs
- `results/` — generated by running simulations

Adjust these paths to match the repository's actual layout.
